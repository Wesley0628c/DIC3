# DIC3 學習心得：Food Guardian 與規格驅動開發

這次整理 Food Guardian 專題提案，讓我重新思考人工智慧應用與實際需求的關係。原先我較關注食譜推薦與保存期限提醒，但在梳理研究動機後，我發現家庭食物浪費還涉及庫存是否完整、食材使用順序，以及使用者能否理解建議。因此，系統設計必須先釐清問題，再決定需要哪些工具。

透過 A 到 F 的摘要架構，我學會依序交代動機、挑戰、解法、方法、評估與預期成果。這個過程也提醒我，功能描述不能取代研究貢獻，必須說明相較既有方法改善了什麼，以及如何驗證。提案階段尚未進行實驗，因此只能提出預期成果，不能把推測寫成已證實的成效。

在閱讀 OpenSpec 與規格驅動開發的概念後，我理解到提案還需要轉化為明確需求、設計決策及可追蹤任務。例如，遇到保存資訊不足的食材，應先要求補充資料；餐點建議也應檢查庫存數量，避免產生看似合理卻無法料理的推薦。

我也體會到，食品安全優先與減少浪費之間需要謹慎取捨。語言模型適合理解需求與組織說明，但安全限制仍須依據可靠資料與規則判斷。同時，文獻引用必須能追溯原始來源，不能直接採用生成內容中的名稱或數字。

目前我已整理摘要、筆記與資訊圖表並上傳 GitHub，接下來仍需完成正式緒論、相關研究及 OpenSpec 文件。我希望逐步建立能被檢查與驗證的提案，讓技術選擇真正回應家庭食材管理的問題。
